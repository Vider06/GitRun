## Trust and evidence rules

The workflow-facing API is a closed set of explicit operations. Authorization depends on peer/container identity, the authoritative GitHub run/job, effective repository/API/resource policy, and the command policy where required. Workflow-visible identity strings alone are not credentials. Docker-socket access, when explicitly allowed for a repository, remains host-level authority.

Kitty cannot bypass the deterministic scheduler, GSR authorization, global capacity limits or resource-pressure backpressure. Missing settings, invalid/corrupt data, stale observations or persistence errors return to deterministic scheduling. Its quality score is a heuristic readiness measure, not a probability.

## Deployment checks not covered by the green CI

- Live desktop `pkexec` prompt and real install/uninstall/reinstall privilege transitions.
- Provisioning and recovery on actual KVM/libvirt and VirtualBox hosts.
- A complete authorized GitDockRun disconnect request through the public/local API endpoint with a real client lifecycle.
- Migration tests for every existing or customized runner image and GitDockRun control volume.
- Direct privileged policy edits that intentionally bypass the supported sidecar-lock writer protocol.
- The number and disposition of alerts in GitHub's Security tab; a successful CodeQL workflow does not report that inventory.
