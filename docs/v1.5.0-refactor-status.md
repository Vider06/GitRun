## 1. UI performance and polish — PARTIAL

### Completed in this PR
- Removed the misleading static “UI READY” status and made the version footer report loading, a real version, or an unavailable state.
- Made the sidebar reversible and persistent; improved active navigation and accessibility metadata.
- Secondary Tauri views and first-run setup are dynamically imported only when needed; the initial module graph eagerly loads only the shared helpers and Overview. Lazy imports check the navigation generation before rendering so a late module load cannot replace a newer page.
- Repository policy navigation now uses one `get_repo_dashboard_bootstrap` IPC call for repository detail, requirements, settings and config. This avoids four separate IPC calls and repeated config/settings reads before the form can render; GitHub runner/activity telemetry remains asynchronous and cannot block or overwrite policy edits.
- Centralized common layout/error styling and removed unnecessary static inline styling from the audited views.
- Logs no longer fetch the system journal when the Security Events tab is opened; they load the journal on demand.
- Overview reuses its original telemetry promise after the fast first paint instead of starting a second batch of telemetry requests.
- Repository navigation now waits only for local repository detail, requirements, settings and config; runner/activity GitHub telemetry updates after the policy UI renders, without replacing the form or discarding edits. Late telemetry results are ignored after navigation changes.
- Removed the decorative metric-card circles, translucent topbar, modal backdrop blur and elevated modal/toast shadows; panels use solid surfaces and clear borders instead of glass/floating-card styling.
- The dashboard requests only the latest bounded event window; the event reader seeks from the end of the JSONL file.
- Overview's critical-event count streams the JSONL file instead of materializing its full contents.

### Still missing
- A reproducible before/after baseline for startup time, navigation latency, idle CPU, peak memory, log rendering and bundle/package size. This requires running the actual Tauri desktop app on a target machine; source-only inspection cannot produce trustworthy timings, so this remains for a local runtime pass.
- Manual end-to-end UI verification on the actual Tauri desktop runtime and representative large event histories.

### Event queue retention implemented
- The active JSONL queue rotates before a new record would take it past 16 MiB; up to ten archives are retained and the oldest archives are pruned. The nominal retained storage is approximately 176 MiB maximum, plus a single oversized event.
- A shared sidecar advisory lock coordinates current Unix producers/readers around append, rotation and reads. Full-history reads and critical counts include retained archives; tail reads remain bounded and span archive boundaries.
- This is deliberately finite retention, not a permanent compliance archive: older events are eventually deleted. Operators needing longer retention must export events to an external durable store.

### GitDockRun live mount — implementation present; final adversarial review remains partial

- API contract: GitRunOperation::Mount / Unmount, strict argument allowlists, --mount SOURCE --target PATH --docked runner, --unmount MOUNT_ID --docked runner; mode defaults to read-only.
- Policy: source rules are explicit and deny-by-default; canonical sources and explicit denies are enforced. GSR and the execution backend both check the current effective API/resource/mountable policy, and the backend re-reads the policy immediately before the mount side effect, after durably saving `attaching`. Equal-specificity allow rules combine restrictions conservatively. Independent policy writers are not serialized after this final read; that remaining race is documented.
- Runtime: host sources are staged in a private mount namespace, checked against the original pinned inode, cloned into a detached tree and attached by descriptor. Read-only/NOSUID/NODEV attributes are set on the detached mount tree before attachment, avoiding a writable exposure window. Remount/unmount helpers recheck the expected kernel mount ID with statx; operations fail closed after inspecting CapEff, CapPrm, CapInh, CapAmb and CapBnd for every visible thread in the bound container cgroup, with regression coverage for current and reacquirable CAP_SYS_ADMIN. The backend now rechecks current policy after persisting the `attaching` state and immediately before entering the namespace worker. Target paths are validated against a clean allowlist and no-symlink resolution. External policy writers are not serialized with this final check, so changes made after that read remain an open cross-process race.
- Registry/lifecycle: a durable, cross-process-locked mount registry persists intent, source device/inode, kernel mount ID and recovery state. Disconnect cleans up job-owned leases before removing the binding; workflow reconciliation cleans completed jobs. Interrupted binds now have a durable `attaching` state before the privileged worker starts; only `preparing` proves the bind was not entered. Missing/ambiguous/mismatched leases are preserved rather than unmounted by path guesswork.
- Follow-up audit: added a subprocess regression test proving the mount-registry advisory lock blocks a separately running process until the owner releases it (the earlier test covered independent file opens within one process). The privileged smoke test already exercises competing mounts, `preparing`/`attaching` crash recovery, and source-identity mismatch. `docs/SECURITY_MODEL.md` now gives the safe operator rule for preserved leases: verify the exact container, target, source device/inode and mount ID; never delete an ambiguous lease or unmount by pathname alone.
- UI/docs: repository mount policy controls and global Mount/Unmount API operation toggles are present with runtime-aware copy; API/security documentation describes the local Linux-only contract.
