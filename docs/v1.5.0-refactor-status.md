## 1. UI performance and polish — PARTIAL

### Completed in this PR
- Removed the misleading static “UI READY” status and made the version footer report loading, a real version, or an unavailable state.
- Made the sidebar reversible and persistent; improved active navigation and accessibility metadata.
- Centralized common layout/error styling and removed unnecessary static inline styling from the audited views.
- Logs no longer fetch the system journal when the Security Events tab is opened; they load the journal on demand.
- Overview reuses its original telemetry promise after the fast first paint instead of starting a second batch of telemetry requests.

- A retention/rotation plan for the append-only event file. The new dashboard read path bounds memory for recent logs, but an exact recent-critical count still scans the durable file and the file itself can grow indefinitely.

## 2. Expected-vs-actual behavior contracts — NOT COMPLETE

### Completed
- Added regression tests for reading the newest events in file order, zero limit, and a JSONL file without a trailing newline.
- The dashboard save path compares submitted config/settings snapshots with current values and rejects a stale screen instead of silently accepting an obviously stale save.
- Config and GitRun settings writes issued by Tauri commands now share a process-wide mutex, so concurrent dashboard save commands cannot both pass the stale-snapshot check before either writes. A unit test covers lock serialization. This does not coordinate independent external processes.

### Still missing
- A crate-by-crate contract inventory: responsibilities, inputs, outputs, invariants, side effects, limits, timeouts, failure modes and recovery semantics.
- A requirements-to-code-to-test matrix and explicit evidence for each contract.
- Add direct tests for stale-save rejection and repeated successful saves in the same UI session.
- The in-process Tauri writers are serialized, but updates from external processes (for example CLI/service writers) are not covered by this mutex. If concurrent cross-process writes are a supported scenario, add a shared OS-level lock or atomic revision/CAS protocol.

## 3. Code consistency and missing enforcement — PARTIAL

### Other findings already addressed
- The repository screen explains that repository-level API overrides cannot re-enable globally disabled capabilities.
- Global Logic Containers rules explain their immediate, separate persistence behavior.
- The direct-Docker-socket opt-in confirmation and backend validation remain in place.

### GitDockRun live mount — implementation present; final CI/security verification pending

- API contract: GitRunOperation::Mount / Unmount, strict argument allowlists, --mount SOURCE --target PATH --docked runner, --unmount MOUNT_ID --docked runner; mode defaults to read-only.
- Policy: source rules are explicit and deny-by-default; canonical sources and explicit denies are enforced. GSR and the execution backend both check the current effective API/resource/mountable policy, and the backend re-reads the policy immediately before the mount side effect. Equal-specificity allow rules combine restrictions conservatively.
- Runtime: host sources are staged in a private mount namespace, checked against the original pinned inode, cloned into a detached tree and attached by descriptor. Read-only/NOSUID/NODEV attributes are set on the detached mount tree before attachment, avoiding a writable exposure window. Remount/unmount helpers recheck the expected kernel mount ID with statx; operations fail closed for containers with CAP_SYS_ADMIN effective or in the bounding set. Target paths are validated against a clean allowlist and no-symlink resolution.
- Registry/lifecycle: a durable, cross-process-locked mount registry persists intent, source device/inode, kernel mount ID and recovery state. Disconnect cleans up job-owned leases before removing the binding; workflow reconciliation cleans completed jobs. Interrupted binds recover only at the exact recorded target with matching source identity; missing/ambiguous/mismatched leases are preserved rather than unmounted by path guesswork.
- UI/docs: repository mount policy controls and global Mount/Unmount API operation toggles are present with runtime-aware copy; API/security documentation describes the local Linux-only contract.

### Still open
- The mount helper is privileged code. Compilation alone is not evidence that the kernel operation is correct; the real-container test and subsequent security review are required.
- Live mounts currently support local Linux Docker only, require a pre-existing target under the documented safe prefixes, reject symlink components, and require directory destinations to be empty. Windows, macOS and remote/VM Docker daemons are unsupported in this version.
- The broader audit for other settings that are declared but not consumed, swallowed errors, duplicated implementations and incomplete validation remains open.
