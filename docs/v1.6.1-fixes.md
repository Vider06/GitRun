# GitRun 1.6.1 — runtime, dashboard, and package lifecycle fixes

This patch release addresses the runtime failures reported after the 1.6.0 rollout.

## Dashboard and protected state

- Route GSR event reads and critical-event counts, plus Kitty/adaptive-resource settings and status reads, through fixed-purpose, root-authorized CLI helpers for system installations. The Overview no longer requests elevation during startup merely to calculate a security-event count; protected GSR or Kitty status is requested only when the operator opens the corresponding view.
- Route Logic Containers policy reads/writes, VM configuration reads/writes, pending hypervisor decisions, autoscaler-independent GitDockRun requirement reads, and the protected PID check through narrowly scoped helpers. The helpers read the trusted system configuration from `/etc/gitrun/gitrun.env`, validate the state directory and file types/owners/permissions, cap payloads, and do not accept arbitrary caller-supplied filesystem paths.
- Preserve private state-file permissions. VM definitions are staged with mode `0600`; the change does not make `/var/lib/gitrun` or `/run/gitrun` world-writable and does not grant the desktop user access to the runner API socket.
- Resolve `journalctl` by its fixed system path on Linux so a desktop-launched Tauri app does not depend on an interactive shell's `PATH`.

## Scheduler recovery and GitHub permissions

- When the runner bridge disappears between inspection and container creation, the scheduler revalidates/recreates the configured bridge under the existing `gitrun.managed=true` and Linux inter-container-isolation checks, then retries the runner creation once. A bridge with the wrong metadata is never accepted as a substitute.
- A GitHub 403 caused by `Resource not accessible by integration` now reports the required repository runner permissions and points operators to the GitHub App installation or token scope that must be corrected. GitRun intentionally does not bypass GitHub's authorization checks or retry a permanent permissions failure.

For a GitHub App, approve/install repository **Administration: read** for runner listing and **Administration: write** for runner registration/removal operations. A fine-grained PAT needs the corresponding repository Administration permission; a classic PAT needs `repo` scope and sufficient repository access. See the [GitHub self-hosted runners REST API documentation](https://docs.github.com/en/rest/actions/self-hosted-runners).

## Package lifecycle

- Ordinary Debian package removal now stops/disables GitRun's systemd services but preserves the operator's configuration, state and data. Full destructive cleanup remains the explicit `gitrun uninstall` operation.
- Release validation ensures `DEBIAN/prerm` no longer invokes the destructive package-uninstall hook.

## SemVer

GitRun package version and dashboard package metadata advance to `1.6.1`. Every workspace crate receives a patch-version increment, and `Cargo.lock` is updated to the matching local package versions.
