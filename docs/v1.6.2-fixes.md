# GitRun v1.6.2 fixes

## Dashboard: recover from protected settings permissions

- Route dashboard reads of GitRun security policy through a fixed-purpose, administrator-authorized CLI helper only when the normal read fails with `PermissionDenied`.
- Cover the Settings screen, repository bootstrap, repository API policy view, and the policy re-checks performed by save operations.
- Validate the trusted system configuration, state directory, settings-file ownership/type/link count/permissions and payload size before returning policy data.
- Keep normal user-readable installations on the non-privileged path; do not weaken the permissions on `/var/lib/gitrun`, `gitrun-settings.json`, or the API socket.
- Add a hidden CLI entry point and argument-parser regression coverage for the authorized read operation.

This is a follow-up to the v1.6.1 runtime/dashboard recovery patch; it addresses remaining direct reads of the protected security-settings file.

If authorization is unavailable or the trusted helper is missing, GitRun returns a specific error; it never weakens filesystem permissions as a fallback.
