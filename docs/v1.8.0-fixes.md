# GitRun 1.8.0 source-line notes

This document records the source changes grouped into the 1.8.0 version-alignment PR. It does not assert that a signed or installable 1.8.0 release has been published; check [GitHub Releases](https://github.com/Vider06/GitRun/releases).

## CLI and terminal management

- Added the keyboard-driven `gitrun manage` terminal management console for headless environments. It uses the same validated backend operations as the dashboard instead of maintaining an independent settings implementation.
- Standard CLI invocations show the mascot by default; `--no-cat` is the explicit opt-out. Internal dashboard and recovery child-process launches pass `--no-cat` so terminal output remains clean and does not conflict with the parent application's rendering.
- Help, version and argument-error paths use the shared presenter policy; malformed version-flag ordering returns a failure state and the expected non-zero exit code.

## Runtime and regression-test fixes

- Privileged and unprivileged dashboard command launchers explicitly suppress the child CLI mascot unless the caller has already supplied `--no-cat`.
- Recovery launches for service repair, recovery checks, dashboard and scheduler use the same explicit suppression.
- Linux process-control tests serialize their fork/ptrace/waitpid operations and retry interrupted `waitpid` calls, preventing one test from collecting another test's child process.

## Version alignment

The product/source version is recorded as `1.8.0` in `version.txt` and the dashboard package/Tauri metadata. Only crates changed by the preceding CLI/TUI and process-launch work receive patch bumps:

| Crate | Previous | New |
|---|---:|---:|
| `gitrun-cli` | 0.13.2 | 0.13.3 |
| `gitrun-dashboard-tauri` | 0.11.0 | 0.11.1 |
| `gitrun-gsr` | 0.6.2 | 0.6.3 |
| `gitrun-recovery` | 0.6.6 | 0.6.7 |

The Recovery Tauri configuration version is also advanced from `0.4.1` to `0.4.2`. Other Rust crates retain their independent SemVer versions; a product release does not require changing every crate version when its source did not change.

## Verification boundary

The version-only edits do not replace validation. CI must confirm that the workspace lockfile remains valid, all crate tests pass, both Tauri applications build, and CLI/TUI behavior remains correct. Interactive privileged desktop prompts, actual host repair and VM lifecycle behavior still require validation on the target environment.
