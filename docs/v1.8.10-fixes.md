# GitRun 1.8.10 source-line notes

This document records the source changes grouped into the 1.8.10 patch line. It does not assert that a signed or installable 1.8.10 release has been published; check [GitHub Releases](https://github.com/Vider06/GitRun/releases).

## Docker runner seccomp profile

- Treat `GITRUN_RUNNER_SECCOMP_PROFILE=default` as a sentinel for Docker's built-in default seccomp profile.
- Do not emit `--security-opt seccomp=default`: Docker interprets `default` as a profile path, which made runner creation fail with `open default: no such file or directory`.
- Explicit daemon-visible seccomp profile paths are still passed to Docker; `unconfined` remains subject to the existing separate unsafe-runner opt-in check.
- Add unit tests for both the built-in default and an explicit profile path.

## Main Library restore diagnostics

- Remove the quiet flag from the transient systemd invocation, so startup errors are not suppressed.
- Assign each operation a distinct, named transient unit while keeping the existing sandbox properties and restricting writable access to `/usr/share/gitrun/library`.
- If the invocation returns a failure without output, query the trusted root-owned `journalctl` executable for that exact unit and attach a bounded diagnostic to the error. If the journal is unavailable, show the exact journal command operators can run.

## Version alignment

The source/product target is `1.8.10` in `version.txt`. Only crates with runtime source changes receive patch bumps: `gitrun-scheduler` 0.11.5 → 0.11.6 and `gitrun-recovery` 0.6.11 → 0.6.12. `Cargo.lock` and current-source Markdown markers are synchronized.

## Verification boundary

CI must validate the new Docker argument tests and recovery code. On MainNode, verify that runner creation no longer passes `seccomp=default`, and retry Restore Main Library to confirm either a successful signed restore or a specific systemd/journal diagnostic. A passing JSON syntax scan alone does not prove this recovery action succeeded.
