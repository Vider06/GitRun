## Local runner-image refresh

- Build the Workbench runner image from the Dockerfile embedded in the signed GitRun release instead of silently fetching an older independently pinned Premade Dockerfile.
- Persist the selected runner profile and fingerprint the Dockerfile, entrypoint, full trusted GSR build context and file modes. If the fingerprint matches the current image label, skip the rebuild.
- Build a changed image under a temporary tag. Before promoting it, validate the fingerprint and the exact `/bin/bash.gitrun-real` entrypoint, then run the actual entrypoint with a runtime `/run/gitrun` tmpfs to verify that the protected policy and required GSR executables are prepared.
- If the build or validation fails, keep the existing image tag and containers unchanged and report an actionable error.
- Make GTUU refresh trusted local images before comparing image IDs. Once a new image is validated, ask GTUU to reconcile eligible permanent runners. Busy runners remain untouched and are reconciled by a later run; dynamic runners use the refreshed image on normal recreation.
- Keep registry-qualified images on the existing signed-manifest and digest-verification route.
