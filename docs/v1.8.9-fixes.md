# GitRun 1.8.9 source-line notes

This document records the source changes grouped into the 1.8.9 patch line. It does not assert that a signed or installable 1.8.9 release has been published; check [GitHub Releases](https://github.com/Vider06/GitRun/releases).

## Recovery and privileged write boundary

- The official Main Library restore now runs in a dedicated transient systemd unit. This avoids inheriting the Control Manager's read-only mount namespace when the Control Manager starts the recovery child process.
- The transient unit keeps `ProtectSystem=full`, `ProtectHome=yes` and `NoNewPrivileges=yes`, and adds write access only to `/usr/share/gitrun/library`.
- The restore continues to use the installed, trusted GitRun binary and signed release manifest. Active configuration under `/etc/gitrun` is not replaced by this operation.

## Doctor diagnostics

- When the current user is unprivileged on a protected system install and the Control Manager is available, permission-denied paths in the protected JSON scan are reported as informational skips rather than as corrupt JSON.
- The report states how many protected paths were skipped and directs the operator to `sudo gitrun doctor` for full validation.
- Malformed JSON, unsafe filesystem objects and unexpected permission failures remain visible as warnings or failures.

## Version alignment

The source/product target is `1.8.9` in `version.txt`. All 11 workspace crates receive patch bumps, with `Cargo.lock` and `crates/gitrun-setup/src/runner-bootstrap.lock` synchronized. Current-source Markdown markers are synchronized by `scripts/sync-markdown-version.py`.

## Verification boundary

The code and lockfile changes are subject to CI validation. The signed Main Library restore should also be exercised on a system install whose Control Manager has `ProtectSystem=full`; the non-root doctor output should be checked to confirm skipped files are clearly disclosed and that `sudo gitrun doctor` still validates the protected JSON contents.
